# 🧑‍💻 프론트엔드 기초 포트폴리오 (Vanilla JS)

외부 라이브러리(React, jQuery 등) 없이 순수 HTML, CSS, JavaScript만을 사용하여 제작한 반응형 웹 포트폴리오입니다. 단순한 화면 구현을 넘어, **'상태 관리(State Management)', '모바일 퍼스트(Mobile First)', '관심사 분리(SoC)'** 등 프론트엔드 개발의 핵심 원리를 체득하는 데 목적을 두었습니다.

## 📌 핵심 학습 및 고민의 흔적 (How & Why)

### 1. 파일 구조와 관심사 분리 (HTML/CSS/JS)
HTML, CSS, JS를 각각 독립된 파일로 분리하여 **관심사 분리(Separation of Concerns)** 원칙을 지켰습니다. HTML은 뼈대(구조)만, CSS는 디자인만, JS는 동작만 담당하게 함으로써 코드 가독성을 높이고 유지보수를 용이하게 만들었습니다.

### 2. 시맨틱 태그 (Semantic HTML)
`div` 태그 남용을 지양하고 `<header>`, `<nav>`, `<main>`, `<section>`, `<footer>` 등의 시맨틱 태그를 구조에 맞게 배치했습니다. 이는 **스크린 리더기의 웹 접근성 향상**과 **검색 엔진 최적화(SEO)**라는 분명한 목적을 위해 선택한 기준입니다.

### 3. CSS 변수 활용과 모바일 퍼스트 전략
* **CSS 변수(`:root`) 도입:** 색상과 폰트 등 반복되는 스타일을 변수로 관리하여 테마(다크 모드) 전환을 매우 쉽게 구현했고, 추후 디자인 변경 시 변수 값 하나만 바꾸면 전체가 적용되도록 효율성을 높였습니다.
* **Mobile-First 접근법:** 모바일 화면의 CSS를 기본으로 작성하고, `@media (min-width: 768px)`를 통해 태블릿 및 데스크톱 레이아웃을 점진적으로 확장(Progressive Enhancement)했습니다. 불필요한 미디어 쿼리 덮어쓰기를 방지하고, 모바일 기기에서의 렌더링 성능을 높이기 위한 선택입니다.

### 4. Flexbox vs Grid의 명확한 역할 구분
* **Flexbox:** `header`의 로고와 메뉴, `form` 요소 등 **1차원 정렬(가로 혹은 세로)**이 필요한 곳에 적용했습니다.
* **CSS Grid:** 프로젝트 카드 목록처럼 브라우저 넓이에 따라 1줄, 2줄, 3줄로 **2차원 바둑판식 자동 배치**가 필요한 곳에 `grid-template-columns: repeat(auto-fit, minmax(300px, 1fr))`를 적용하여 완벽한 반응형을 구현했습니다.

### 5. 인라인 이벤트 핸들러 지양과 DOM 조작
HTML 요소 내부에 `onclick="..."` 속성을 쓰지 않고, 자바스크립트에서 `addEventListener`를 사용하여 이벤트를 연결했습니다. HTML과 JS의 결합도를 낮추고, 하나의 요소에 여러 이벤트를 충돌 없이 부착하기 위해서입니다.

### 6. ⭐️ 상태 객체(STATE) 관리를 통한 단방향 데이터 흐름
기능이 늘어날수록 전역 변수가 흩어져 발생하는 버그를 막기 위해, 애플리케이션의 핵심 데이터를 `STATE` 객체로 통합했습니다. 모든 기능은 다음과 같은 단방향 흐름으로 작동합니다.
> **사용자 이벤트 발생 ➡️ `STATE` 객체 값 업데이트 ➡️ `render()` 함수 호출 (화면 업데이트)**
*(예: 필터 버튼 클릭 -> `STATE.filter` 값 변경 -> `renderProjects()`가 상태를 읽고 화면 재렌더링)*
이 패턴은 추후 학습할 React의 상태(State) 및 렌더링 동작 원리와 동일한 구조입니다.

### 7. 비동기 통신과 4가지 상태에 따른 UI 처리
`async/await`와 `try/catch` 구문을 사용하여 GitHub API 호출 시 발생할 수 있는 비동기 로직을 직관적이고 안전하게 제어했습니다.
API 호출 결과를 `STATE.projects.status` 값에 반영하여, 다음 4가지 상태에 따른 피드백을 사용자에게 명확히 전달합니다.
* `loading`: 데이터를 기다리는 동안 스피너 표시
* `success`: 데이터를 받아 `map()`과 `filter()` 배열 메서드를 활용해 HTML 문자열로 가공 후 렌더링
* `error`: Rate Limit 등 통신 실패 시 에러 메시지와 재시도 버튼 표시
* `empty`: 리포지토리가 없는 경우의 빈 화면 처리

### 8. 폼 유효성 검사 UX
Submit 이벤트 발생 시 빈 값과 이메일 정규식 오류를 검증합니다. 이때 에러가 발생한 입력 폼은 사용자가 다시 타이핑을 시작하는 순간(`input` 이벤트 감지) 즉각적으로 에러 메시지를 숨겨주어 사용자 경험(UX)을 향상시켰습니다.
